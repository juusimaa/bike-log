# Hosted deployment architecture

> Superseded for hosting by [decision 0007](0007-upcloud-hosting.md) (2026-10-14): Bike Log moves to the owner's UpCloud server. The backup format, storage and restore rehearsal described here still apply.

Approved design for the first hosted slice ([spec 004](../../specs/004-hosted-deployment/spec.md)): one Azure Container App in Sweden Central runs the existing web app and API as two containers that share `localhost`, scales to zero, and uses the Aiven free PostgreSQL service ([decision 0003](0003-aiven-postgres-and-container-apps-hosting.md)) over verified TLS. Recorded on 2026-10-14 from the plan's decisions D1–D18 ([research](../../specs/004-hosted-deployment/research.md)) and what implementation found.

Context: the web app and API were tested only on loopback. Hosting must keep the invite-only sign-in and per-owner checks of [decision 0002](0002-auth0-invite-only-identity.md), stay within a €10 monthly budget, keep secrets and personal values out of a public repository, and prove that records can be recovered before any real record is entered.

Design:

- **One app, two containers.** `ca-bikelog` runs `web` (external HTTPS ingress on port 3000) and `api` (bound to `127.0.0.1:5080`, no ingress), so the API is reachable only through the web proxy, as in `compose.app.yaml`. One replica at most, Consumption profile only, `minReplicas: 0`. The platform's probes cannot reach a loopback-bound API, so only `web` has probes; its `/healthz` succeeds only when the API's `/health/ready` does.
- **Bootstrap and main templates.** `infra/bootstrap.bicep`, run once by the owner, creates the budget, both managed identities, the GitHub federated credential, Key Vault, backup storage, a custom backup role and every role assignment. `infra/main.bicep`, run by CI with Contributor on the resource group, creates the log workspace, environment, app, jobs and alerts, and declares no role assignments (checked in CI). A compromised workflow therefore cannot grant itself new access.
- **Key Vault references.** The app and jobs reference versionless Key Vault secrets through `id-bikelog-app`. The Aiven CA certificate is the only secret mounted as a file (`/mnt/secrets`). GitHub holds no credentials; the deploy signs in with short-lived OIDC tokens limited to the `production` environment. The owner's email, the database host and the ingress allow-list are GitHub environment secrets only so that the public workflow logs mask them.
- **Add-only backups with a snapshot manifest.** A daily job exports a repeatable-read snapshot, records exact row counts, stored usage totals and the latest migration from it, then runs `pg_dump --snapshot`, so the manifest and the dump describe the same moment. Both are uploaded as create-only blobs with a role that has `blobs/add/action` and `blobs/read` only, so the job cannot overwrite or delete; a lifecycle rule deletes blobs after 35 days. A restore rehearsal on the owner's Mac restores into a fresh container and compares it with the manifest. A metric alert emails the owner when a day has no successful backup.
- **Operator job.** Pilot riders are provisioned, disabled and enabled by `job-bikelog-ops`, which runs the API image in operator mode. The API accepts a hosted target only in Production, in Authenticated mode, with `SSL Mode=VerifyFull`, a root certificate and a host equal to the configured `Operator:HostedDatabaseHost`; the local rule is unchanged. `scripts/hosted/hosted.sh` sets the job's arguments with an ARM patch and starts it without overrides, because `az containerapp job start --args` replaces the whole container and drops its secrets and mount, and `az … --args` cannot take values that start with `--`.
- **Public origin from configuration.** The web app derives its public origin from `WEB_PUBLIC_ORIGIN` once the `Host` header matches, rejects `X-Forwarded-Proto: http`, and never trusts `X-Forwarded-Host` or the scheme of `request.url`. The OIDC callback rebuilds its URL on that origin, because the OIDC client derives `redirect_uri` from it. HSTS is always sent: Next.js resolves headers at build time and one image serves every origin, and browsers ignore HSTS over plain HTTP.
- **No database IP allow-list.** Container Apps has no stable outbound address without a NAT gateway, which the budget excludes. TLS with certificate verification and a long password held only in Key Vault are the protection, as decision 0003 named.
- **Aiven region.** The free plan places the service in a region Aiven chooses. Setup records it, and a region outside the EU stops the rollout until a paid plan in `azure-sweden-central` is estimated and approved.
- **Ingress gate.** The first deployment admits only the owner's address. The allow-list is cleared only after the hosted sign-in and refusal checks pass (constitution IV).

Alternatives rejected:

- Two container apps with internal ingress for the API: more resources, and the proxy would need a non-loopback upstream.
- One template with CI holding Role Based Access Control Administrator: broader rights for CI than the rare role changes justify.
- Blob immutability policies: lifecycle deletion does not work on immutable containers, which would break the 35-day retention.
- Azure Container Registry: a monthly charge; the GHCR packages are public instead.
- `minReplicas: 1`: no cold start, but idle charges around the clock, outside the approved estimate.

Consequences: the environment can be recreated from the two templates plus [docs/hosting/setup.md](../hosting/setup.md). Cold starts after idle periods are expected (target 30 seconds). Rollback redeploys earlier digests, which requires every migration to stay additive. More replicas, a worker or a larger pool must be checked against Aiven's 20 connections first. Service Bus, the outbox, the worker and Application Insights remain for the asynchronous part of Phase 3.
