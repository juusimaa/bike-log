# Approved UI v1 Connected Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved UI v1 as a local Next.js client that persists and reloads Bike Log workflows through the completed API, including oil/wax reminder settings.

**Architecture:** Next.js App Router in `apps/web` uses a shared OpenAPI-generated TypeScript client in `packages/api-client`. React/TanStack Query manage UI and remote state through a same-origin, fixed-loopback API adapter; the backend remains authoritative for allocation, usage, replacement and reminder calculations. Port the approved visual assets into focused components without porting the prototype's synthetic database/domain logic.

**Tech Stack:** Node.js 24 LTS, Next.js 16/React 19, TypeScript, npm workspaces, plain CSS/CSS modules, openapi-typescript/openapi-fetch, lossless-json, TanStack Query 5, Vitest/Testing Library, Playwright, Temporal polyfill, ESLint/Prettier; existing .NET 10/PostgreSQL 17.

**Spec:** `docs/superpowers/specs/2026-10-02-web-ui-design.md` (approved through the owner’s plan approval). Visual authority: `docs/ui-design/versions/v1/README.md` and immutable assets/checksums.

**Status:** Approved on 2026-10-02 at backend baseline `a5aad25`. Owner authorized committing and locally merging these planning artifacts first, followed by subagent-driven implementation in an isolated worktree. No push/PR or implementation merge is authorized.

## Global Constraints

- Preserve version 1.0 unchanged in its archive.
- The four sections remain Overview, Components, Rides and Maintenance.
- Desktop sidebar becomes the compact navigation at 650 px; content/reminder panels stack by 950 px, with the 1150 px spacing adjustment retained.
- Use local system fonts and the inline bike SVG; no font download, icon service or external image dependency.
- Browser requests use same-origin `/api/...` on `http://127.0.0.1:3000`.
- A Node-runtime Next route handler forwards only the documented methods/paths to the fixed `http://127.0.0.1:5080/api/...` backend, with no cache and no redirects.
- No aggregate is calculated from a fetched page.
- Collection pages use size 50 and opaque nextCursor; Load more appends unique IDs, never guesses totals.
- No localStorage fixture/model store; reload reads the API.
- Switching methods does not log service or reset usage/baseline.
- Read-only requests may retry once; mutations never auto-retry.
- Commits/push/PR require separate authorization.
- Local synthetic web only; no React Native, authentication, remote hosting or backend domain/migration changes in this milestone.

## Review Focus

1. A late response after switching bike/filter must not populate the active view with the previous bike or reuse its cursor — Task 3 keyed-query test.
2. Lost mutation response must preserve input and say outcome uncertain, with refresh/check-history before explicit resubmit — Task 2/4 mutation-state test and Task 9 browser failure injection.
3. DST gaps/overlaps and existing sub-minute timestamps must not silently change stored instants — Task 2 conversion tests, Task 5 untouched-edit test.
4. Empty garage, legacy nullable metadata and no fitted chain must remain usable without invented names or zero-valued reminder success — Tasks 3/4/8 tests.
5. Unsafe int64/decimal values must not round silently or be reposted, and currencies/unknown duration must not be conflated — Task 1 codec and Tasks 3/6 presentation tests.
